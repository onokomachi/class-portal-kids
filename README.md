# class-portal-kids

子ども用の**がくしゅうポータル**。単元アプリ（13本）への入口をまとめ、
「きょうの ふくしゅう」を単元をまたいで出します。

## なぜハブが要るか

単元アプリはそれぞれ別ドメイン（`*.vercel.app` のサブドメイン）なので、
`localStorage` が共有されません。学級コードを毎回アプリごとに入れさせないために、
**ここで1回だけ入れて、各アプリへ引きつぐ**形にしています。

```
ハブ ──▶ https://syo4-gaisu.vercel.app/#c=4-2&n=12
```

- 渡すのは**学級コードと出席番号だけ**。児童IDそのものは載せません
  （共有・ブックマーク・履歴に「なりすませる文字列」を残さないため）
- **クエリではなくハッシュ**。ハッシュはサーバへ送られないので、
  アクセスログに出席番号が残りません

## 見せ方の方針：正答率も順位も出さない

Kluger & DeNisi (1996) の607件のメタ分析では、フィードバックの約3分の1が**負の効果**でした。
分かれ目は注意が「課題そのもの」に向くか「自分の出来不出来」に向くかです。

そこで数字で優劣を示さず、「**つぎに やること**」を前に出します。
「じぶんの のび」も他人と比べる数字ではなく、達成した数だけを出します。

## 氏名はどこにもありません

子どもは「この学級の12番」としか名乗りません。番号と氏名の対応表は先生の手元に残ります。
**この仕組みが丸ごと漏れても、誰のことかは分かりません。**

学級コードを入れなくても各アプリへは行けます——コードを忘れた子が
学習そのものをあきらめることにならないように。

## セットアップ

```bash
cp .env.example .env.local   # URL と publishable key を埋める
npm install
npm run dev
```

どちらも **publishable**（公開前提）のキーです。
secret key / service_role key は絶対に置かないでください。

### 学級を作る

先生が Supabase の SQL Editor で1回だけ作ります。

```sql
insert into public.classes (school_year, grade, class_name, join_code, size)
values (2026, 4, '2組', 'r8-4-2', 35);
```

`join_code` が子どもに伝える合言葉です。名簿に無い番号は拒否されます
（打ちまちがいで幽霊児童を作らないため）。
